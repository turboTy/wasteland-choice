## 产品一句话

玩家扮演携带**奖励系统金手指**的穿越者，进入**存在魔法与空间戒指**的末日世界：**出击搜刮（搜打撤）→ 把资源投入基地建设 → 招募伙伴 → 在世界危机升级中活下去**。核心张力来自"**继续深入还是及时撤离**"——撤回来才是你的，撤不回来就是别人的。

## 核心设计原则（红线）

1. **规则层兜底 LLM**：所有魔法/奖励/风险效果必须落到既有数值层的确定性改动，禁止"无视数值"。
2. **撤离决策必须有真实动机**：搜打撤成立的前提是"损失可感知"。若失败无代价，最优解退化为"搜无可搜再走"。
3. **容器二分不可倒挂**：行囊 = **风险格**（大容量、失败全丢）；戒指 = **安全格**（小容量、失败保底）。**戒指容量任何时刻不得 ≥ 行囊容量**。
4. **金手指不无双**：戒指容量随奖励系统成长解锁（MVP 内 2 次扩容）；奖励是"雪中送炭"非"自动通关"。
5. **双轨对冲**：世界危机升级 → 奖励强度同步提升，保持"我在变强、世界更难"的动态平衡。
6. **队伍张力不自我抵消**：负担真实存在，戒指仅作**延迟缓冲**，不得与"轻度负担"叠加削弱。
7. **基地是安全资产**：出击失败不摧毁已建设施、不清空基地存储——"失败不等于推倒重来"。
8. **扩结构不扩内容**：区域由配置表驱动，结构支持 N 区，**MVP 内容锁 2 区**。
9. **主线由人工把骨架**：主线节点/结局人工定义，LLM 只填充场景文本。
10. **每日机制是叙事装置，不是经济装置**：每日系统抉择**不产大额资源、不含扩容、单独计数**，资源贡献 ≤ 一局总收入的 15%。**无条件签到式发放明确否决**。
11. **时间只有一个锚点**：「日」由**日结算**推进（体力耗尽或主动结束当日），不为净值/床铺/每日抉择各搞一套计时。

## 文档规则（摘要）

### 有效文档判定（三层）

| 优先级 | 判据 |
|---|---|
| **1（主判据）** | **是否位于 `_archive/` 目录内**。不在 = 有效；在 = 归档只读 |
| 2 | 上方索引表的「版本 / 状态」列（🟡 = 有效，「归档」= 失效） |
| 3 | 文件内 `version:` frontmatter（仅作复核） |

> ⚠️ **不要用 `status:` 字段判有效性**——归档件当年未改写元数据，`status` 至今仍是 `draft`，单看它无法区分。**以位置为准。**

### 三个容易搞错的点

1. **两个 `addendum.md` 同名不同物**：门户 `product/brief-addendum.md` = **BRIEF 的玩法详案**；原位 `prds/.../addendum.md` = **PRD 附册**（门户侧叫 `prd-addendum.md`）。门户靠阶段前缀区分，原位靠所在目录（`briefs/` vs `prds/`）区分。
2. **`.memlog.md` 不是文档**：每个原位目录各一份，是 BMAD 的**决策审计日志**（谁在何时定了什么），只用于追溯，**不承载需求口径**。现状：`briefs/` 45 条、`prds/` 21 条。
3. **归档件不可修改**：归档是"当时的样子"的快照。若需修正，改**当前有效版**。

### 一句话记忆

> **看位置**：不在 `_archive/` 里的 4 份才是活的；索引表是入口；`.memlog.md` 是日志不是文档。
