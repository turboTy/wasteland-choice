# BRIEF Memlog — WASTELAND CHOICE（末世求生：抉择）

> BMAD bmad-product-brief (Fast path) 运行记忆。append-only，每行一条，记录决策 / 假设 / 质疑。

- (goal) 用户想做"AI漫剧风格的末世求生 AI 交互体验小游戏"，要求 BMAD 方法开发。
- (direction) 形态定为"LLM 互动生存游戏 + 生存数值面板（体温/饥饿/体力/资源/sanity），漫剧风 UI 后置"，非被动观看型漫剧。
- (decision) 不实时生成视频（成本/延迟硬约束），MVP 文字+面板，画面后置关键帧。
- (decision) 不做发布型（规避 9/1 落地的《微短剧发展管理办法》监管），先自用/demo 验证。
- (decision) 定位为个人兴趣 + BMAD 方法验证载体，非公司主业延伸，MVP 极致轻。
- (insight) 差异化不在"又一个末世剧"，在"决策的真实代价与蝴蝶效应" + 规则层兜底 LLM 幻觉。
- (assumption) A1-A7 见 brief.md v0.1 评审清单。

## v0.2 增补（2026-09-13 18:58）

- (direction) 用户补充核心思路：求生过程中"探索不同区域寻找物资 + 招募伙伴 + 随末日模式升级推进新剧情"。
- (decision) 玩法框架 = 分区推进式（固定地图、逐区解锁、有终局），非 Roguelike 全随机、非纯线性章节。

- (decision) 奖励系统 = **系统流金手指**（主角独有，NPC 无），非通用任务系统。
- (decision) 魔法/空间戒指 = **强设定/核心机制**（参与玩法），非纯背景氛围。
- (decision) 文档存放 = 规范化：产物同步至项目内 `docs/product/`（面向人门户）+ 原位 `_bmad-output/` 保留。

## v0.4 评审与口径统一（2026-09-14 09:50）

- (review) 对 v0.3 做评审核查，发现 **5 处内部不一致 + 2 处缺失**：
  1. 「3 区域」出现三种口径（Scope=含基地 / MVP 表=3含基地 / Success Criteria=≥3 可探索）→ 验收标准会打架；
  2. A7 首个探索区候选含"医院"，与危机表"医院=等级 2 解锁"冲突；
  3. A10「轻度负担 + 戒指对冲」**双重削弱** → 招募零代价、核心张力名存实亡；
  4. A2 目标用户画像与 A3「自用不发布」逻辑冲突；
  5. A14 承诺"容量随成长"但 MVP 只给 1 次扩容 → 爽感尚未建立即结束；
  6. **缺失**：主线剧情由谁生成（人工 vs LLM）——架构级空白；
  7. **缺失**：sanity（写实压抑）与"金手指爽文流"定位的取向冲突。
- (decision) **A7/A10/A11/A14 及区域口径** 经 AskUserQuestion 定案（用户全选推荐项）：
  - 区域 = **3 = 基地 + 2 可探索（超市仓储 / 医院）**；首个探索区 = 超市仓储（与危机 1 级对齐）。
  - 伙伴负担 = **保留真实张力**；戒指改为**延迟缓冲**，明确"两者不得叠加削弱"。
  - 扩容节奏 = **MVP 内 2 次**（初获 + 危机 1→2 节点）。
  - 叙事分工 = **人工写大纲 + LLM 填充场景文本**。
- (assumption) 新增 A16（叙事分工）、A17（sanity 弱化惩罚）、A18（MVP 不做插画）。
- (revision) A2 降级为远期假设；A6 成功信号由百分比门槛改为**定性信号**（10 人样本下 60% = 6 人，统计效力不足）。

- (decision) v0.5 核心玩法主线定案：基地经营 × 搜打撤出击双引擎（A19）
