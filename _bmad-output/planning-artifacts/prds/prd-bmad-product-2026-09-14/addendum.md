# PRD Addendum：技术选型、被否决方案与机制数值

> 本文件承接**不适合放进 PRD 正文**的内容：技术实现细节（属架构）、被否决方案的论证（属决策档案）、机制数值草表（属解决方案设计）、深度风险登记。
> PRD 只回答"系统必须满足什么"；本文件回答"我们打算怎么做，以及为什么没选另一条路"。

## A. 技术形态与选型

### A.1 形态决策（2026-09-14 定案）

**选定：前端 + 轻量后端。**

| 维度 | 结论 |
|---|---|
| 客户端 | 桌面浏览器 Web 应用 |
| 服务端 | 轻量后端进程，职责限于：代理 LLM 请求、持有密钥、可选的存档同步 |
| 部署 | 本地可运行；内测期部署到单机供 10 人访问 |
| 存档 | 浏览器本地持久化（FR-35），后端不做权威存储 |

### A.2 被否决的形态方案

| 方案 | 否决理由 |
|---|---|
| **纯前端静态页** | 内测 10 人需各自申请并填写 API Key。按经验这会显著拉低内测完成率，而 MVP 的核心验证信号（SM-3 主动持续出击）恰恰依赖内测者愿意反复开局。**门槛成本会污染测量结果。** |
| **桌面应用（Tauri / Electron）** | 体验上限最高，但引入跨平台构建、签名、分发三件套。与 BRIEF「MVP 极致轻」直接冲突。收益（更好的本地能力）在本项目中并无真实需求。 |
| **无后端 + 静态托管 + 云函数** | 需要云端账号与配置管理，反而比一个本地后端更重。 |

### A.3 LLM 接入（2026-09-14 定案）

**选定：后端统一持有密钥。**

- 密钥仅存于服务端环境变量，**不进前端产物、不进仓库**。
- 模型可切换（DeepSeek / 通义 / 其他兼容 OpenAI 协议的端点），玩家侧无感。
- 需实现：超时控制、重试、降级到模板文案（对应 FR-30）、按日调用上限与单局调用预算（对应 §8.2）。
- **每日系统抉择的文案**建议在降级路径下改用**静态文案池**（选项效果仍由规则层配置池决定，不受影响），避免每日一次的固定调用推高成本。

**被否决：玩家自填 Key。** 零服务端成本，但把配置负担转移给内测者，且密钥散落在多人浏览器中无法统一吊销。

**被否决：纯 Mock 先跑。** 作为**开发顺序**是合理的（切片期可以先 Mock 跑通规则层），但作为**最终形态**不成立——FR-28/29/31 的核心假设就是"LLM 生成 + 规则层校验"，不接真模型等于没验证这个假设。

### A.4 风险累积的实现归属（v0.5 新增）

**选定：风险累积完全由规则层计算，LLM 不参与。**

- 风险累积是**确定性数值**（搜刮次数 × 区域系数 + 停留时间 × 时间系数 + 事件修正），不引入随机性。
- LLM 仅负责生成事件**文本**，其数值落点由规则层下发（对应 FR-41）。
- 理由：风险曲线是搜打撤体验的骨架。若交给 LLM，会出现"叙事上很危险但数值上很安全"的错位，直接摧毁张力。

### A.5 时间与结算的实现归属（v0.6 新增）

**选定：日推进与日结算完全由规则层实现，不依赖任何计时器。**

- **不用真实时间计时**：日推进只由两个事件触发——① 处于基地且体力耗尽；② 玩家主动「结束当日」（FR-47）。因此**无需 setInterval / 后台任务**，也天然免疫"关掉页面时间还在走"这类问题。
- 日结算是纯函数：`state + day → state'`，输入输出确定，便于存档与测试。
- 理由：一旦引入实时计时，就必须处理离线推进、时钟篡改、内测者挂机等一连串问题，与「MVP 极致轻」冲突。

## B. 机制数值草表（待标定）

> 以下为**初设值**，用于架构与实现起步；实际标定需在垂直切片内通过实测调整。

### B.1 容器与体力

| 项 | 初设 | 说明 |
|---|---|---|
| **物理行囊上限（风险格）** | **6 单位** | 储物设施 2 级可 +1 → 7 |
| **空间戒指容量（安全格）** | **2 格**（初始激活） | 扩容后 4 → 6；**恒小于行囊上限** |
| 发起出击体力成本 | 1 点 | 对应 FR-2 |
| 单次搜刮体力成本 | 1 点 | 对应 FR-3 |
| 移动到撤离点体力成本 | 1–2 点（按距离） | 对应 FR-38 |
| **单日体力池上限** | **待标定（Q11）** | 决定"一天能出击几次"，是 A28 的核心参数 |
| 体力恢复 | **按日结算**恢复固定值（床铺 1 级 +1，2 级再提升） | 对应 FR-47；恢复量即变相的单日行动预算 |

> **⚠️ 关键约束**：戒指容量**任何时刻不得 ≥ 行囊上限**。若二者相等或倒挂，风险格失去意义，FR-20 的二分结构失效。

### B.2 风险累积（v0.5 新增 · 待标定）

| 项 | 初设 | 说明 |
|---|---|---|
| 风险累积函数 | `风险 = Σ(搜刮次数 × 区域风险系数) × (1 + 停留时间系数) + 事件修正` | 对应 FR-39；**递增非线性** |
| 边际递增来源 | 每次搜刮的风险增量随次数上升（如第 n 次增量 = n × 系数） | 制造"再搜一个越来越贵" |
| 风险可见性 | 强度条（绿 → 黄 → 红） | 对应 FR-24 |
| 风险影响 | 驱动遭遇战 / 环境伤害 / 撤离点封锁的概率 | 具体概率曲线待切片实测 |
| 清零时机 | 撤离成功或失联后 |

> **设计意图**：风险必须在**数值上可见**、在**感受上递增**。若玩家感受不到风险在涨，"该撤了"的决策点就不会被触发。

### B.3 出击失败分级（v0.5 新增）

| 层级 | 行囊损失 | 戒指损失 | 附加后果 |
|---|---|---|---|
| 撤离受挫 | 随机损失 50% | 无 | 主角脱身 |
| 失联 | 100% | 无（保底） | 主角重伤（可恢复，恢复期限制出击） |
| 团灭 | 100% | 100% | 本局结束 |

> `[ASSUMPTION]` "按次推进"（A24）意味着出战频率由玩家自己掌控。v0.6 引入**日结算**后，"反复送死"不再是零成本——每过一个游戏日就要支付队伍消耗。但**失败惩罚仍不能仅靠"丢失战利品"**，还必须包含**可感知的额外代价（伤 + 时间）**，否则玩家会陷入"无脑重试"的循环。
> **边界提醒**：失联**不等于**过完一天（FR-40）。失联返回基地后，当日仍需另行触发日结算，两者不可混同。

### B.4 基地设施升级（v0.5 新增）

| 设施 | 1 级效果 | 2 级效果 | 1 级成本 | 2 级成本 |
|---|---|---|---|---|
| 床铺 | 每日体力恢复 +1 | 重伤恢复速度 +100% | 布料 ×2 | 布料 ×4 + 工具 ×1 |
| 火堆 | 基地内体温衰减 -30% | 范围保暖：外出体温衰减 -15% | 木材 ×3 | 木材 ×6 + 燃料 ×2 |
| 净水 | 每日净水产出 +1 | 产出 +2，队伍饮水 -20% | 容器 ×2 | 容器 ×3 + 工具 ×1 |
| 储物 | 基地存储上限 +20 | **行囊上限 +1** | 板材 ×3 | 板材 ×6 + 工具 ×2 |

> **设计意图**：四项设施分别对应恢复、保暖、资源、容量四条线。**储物 2 级提升的是风险格容量（行囊），不是安全格（戒指）**——避免基地建设与金手指功能重叠。
> **"每日"的锚点**：床铺与净水的每日效果均在**日结算**（FR-47）中执行，不再悬空。

### B.5 区域产出与撤离点（v0.5 更新）

| 区域 | 解锁等级 | 主产出 | 风险 | 撤离点 | 备注 |
|---|---|---|---|---|---|
| 超市仓储 | 1（极寒） | 食物、工具、材料 | 遭遇战 | 2 个（入口 / 后巷） | UJ-1 首个出击区 |
| 医院 | 2（疫病） | 药品、医疗器材、线索 | 疾病、遭遇战 | 2 个（正门 / 消防梯） | UJ-3 解锁点 |

概率表与搜刮上限在本表中留空，待切片实测填充——**过早固化产出概率会掩盖数值手感问题**。

### B.6 伙伴与队伍消耗

| 项 | 初设 | 说明 |
|---|---|---|
| 食物消耗 | 随人数**显著增长**（非线性上升） | 对应 FR-11；这是刻意的，非调平不足 |
| 药品消耗 | 有人受伤 / 生病时触发 | 医疗专长可降低 |
| **消耗结算时机** | **日结算**（FR-47 步骤 2） | 不在出击过程中逐条扣减 |
| 忠诚度下降触发 | 诉求长期未满足、**经历出击失败** | 必须可归因，禁止随机下降 |
| 离队阈值 | 低于下限即离队 | 对应 FR-12；叙事核心伙伴的离队需显式设计 |

### B.7 安全格扩容节奏（v0.5 更新）

| 时点 | 安全格容量 | 触发 |
|---|---|---|
| 初始 | 未激活 | 开局 |
| 第 1 次 | 激活，**2 格** | 首次出击产出超出预期（UJ-1 高潮点） |
| 第 2 次 | 2 → **4 格** | 危机 1→2 之间的成长节点 |
| 第 3 次 | 4 → **6 格** | 危机 1→2 升级节点（双轨对冲） |

> `[注意]` MVP 内共 **2 次扩容**（即上表的第 1 次与第 2 次为"初获 + 第 1 次扩容"，第 3 次为第 2 次扩容）。口径以 PRD FR-21 为准：**初始激活 1 次 + 扩容 2 次**，最终容量 6 格。
> **设计意图**：扩容必须发生在"玩家真实感受到容量不足"的时刻，且最终容量**仍小于行囊上限**，否则二分结构失效。
> **解耦**：扩容**只能由 FR-16 的触发式奖励发放**；每日系统抉择不得发放扩容（FR-21、FR-48）。

### B.8 全局时间轴（v0.5 新增）

| 项 | 值 | 说明 |
|---|---|---|
| 存活天数上限 | **14 天** | A26；内测标定 |
| 危机等级 1 区间 | 第 1–7 天 | 解锁超市仓储 |
| 危机等级 2 区间 | 第 8–14 天 | 解锁医院 |
| 预期出击次数 | ≥6 次 | 不设单次时长，一天内可多次 |
| 终局路径 | 存活满 14 天结算 / 体温或饥饿归零团灭 | 对应 FR-34 |
| **日推进触发** | **体力耗尽（基地内）或主动「结束当日」** | 对应 FR-47；无实时计时器 |

### B.9 时间基准与每日系统抉择（v0.6 新增 · 待标定）

#### B.9.1 日结算执行顺序

| 序 | 步骤 | 说明 |
|---|---|---|
| 1 | **设施产出** | 净水按日产出（FR-44） |
| 2 | **队伍消耗** | 按人数计食物/药品（FR-11） |
| 3 | **数值衰减** | 体温/饥饿按当前危机等级衰减（FR-25） |
| 4 | **重伤恢复** | 受床铺等级修正（FR-40、FR-43） |
| → | **存活天数 +1** | 驱动危机等级（FR-13）；达 14 天触发终局（FR-34） |
| → | **触发每日系统抉择** | FR-48 |

> **顺序不可交换**：先产出再消耗（玩家当天建的净水能吃到当天产出），先消耗再衰减（缺口才会真实转化为饥饿压力）。若交换，会出现"建了净水却仍当天饿死"这类反直觉结果。

#### B.9.2 每日系统抉择数值草表

| 项 | 初设 | 说明 |
|---|---|---|
| 触发频率 | **每日 1 次**，一局上限 **14 次** | 与存活天数封顶一致；不累积、不可补领 |
| 选项数 | **3 个** | 对应 FR-32 的选项范围 |
| 效果类别 | **信息类 / 能力类 / 象征性小额物资** | 三类配比待标定（Q10） |
| 信息类示例 | 揭示某区域风险走向 / 撤离点可用性 / 稀有 NPC 大致方位 | 必须是**真实存在的游戏内实体**（继承 FR-17 纪律） |
| 能力类示例 | 当日"危险感知"（降低遭遇概率）/ 当日行囊 +1 / 当日体温衰减 -20% | 以**当日或有限天数**为限 |
| 象征性物资 | 一小包压缩饼干级（**不构成收入来源**） | 仅用于维持"系统会给你东西"的叙事手感 |
| **资源占比上限** | **≤ 一局总资源收入 15%** | 规则层参数表约束，可配置（FR-49） |
| **计数口径** | **单独计数**，不并入 FR-16 的"≥4 次" | 防止 SM-1 变成送分题、SM-C2 失效 |
| 明确禁止 | ❌ 空间扩容；❌ 同时缓解体温+饥饿+体力；❌ 永久数值提升 | 见 FR-48、FR-49 |

#### B.9.3 反闲置守卫（测试用例）

| 用例 | 期望结果 |
|---|---|
| 玩家**仅领取每日系统抉择、从不发起出击** | **必须在 14 天内因资源枯竭触发团灭或进入严重衰减** |
| 玩家反复「结束当日」以刷取每日抉择 | 每次结算都扣当日队伍消耗，**资源被快速吃穿**，自然封顶 |
| 每日抉择 + 出击产出合计 | 每日抉择的资源贡献占比 **≤15%**（可测） |

> **设计意图**：每日系统抉择是**叙事装置**，不是经济装置。它在设计上被刻意放在"风险—产出"平面的**低产出端**——提供的是**信息与决策**，而不是资源。这样它既不与出击争夺经济主导权，又能让「系统」这个角色每天出场一次，持续承载 A15 的悬念钩子。

#### B.9.4 为什么否决"无条件签到"（优先级最高的否决项）

| 通道 | 玩家承担的风险 | 产出 | 判定 |
|---|---|---|---|
| 出击产出 | 高 | 高 | ✅ 符合"高风险换高收益" |
| 基地设施产出 | 低 | 低 | ✅ 稳定但有限 |
| **无条件签到发放资源** | **零** | **可达中段** | ❌ **帕累托支配**——同等产出下风险最低，理性玩家的最优解变为"每天上线领一下、不出门" |

**这是结构性缺陷，不是数值问题**：它替代出击动机 → 撤离点前的恐惧消失 → 搜打撤退化为扫荡模式。与 v0.5 已否决的"戒指大容量全保底"属**同一类错误**。

**但须客观说明**：在网文系统流语境下，「每日签到」是读者接受度极高、叙事自然度很高的设定。**问题不在机制本身，而在它被当成经济装置使用**。因此本项目的处置是**改定位**（叙事装置），而非**删除机制**。

## C. 被否决的设计（决策档案）

> 这些是已明确否决、但容易在实现阶段被"好心"加回来的设计。**记录下来是为了防止回流。**

| 被否决设计 | 为什么否决 | 若回流会导致 |
|---|---|---|
| **无条件签到式每日资源发放**（v0.6 高危） | 零风险送出中段产出 → 落于支配区 | **替代出击动机、架空撤离决策、SM-C2 失效**，与"戒指大容量保底"同源 |
| **每日奖励并入 FR-16 的"≥4 次"计数**（v0.6） | 14 次每日抉择会让奖励总数虚高 | SM-1 变成送分题、SM-C2 反向指标形同虚设 |
| **每日抉择发放空间扩容**（v0.6） | 扩容必须绑危机等级（A14），否则难度塌陷 | 金手指成长节奏失控，安全格提前膨胀 |
| **以真实时间 / 离线时长作为每日奖励条件**（v0.6） | 本项目无留存 KPI，该机制的原始动机不成立 | 引入实时计时器，需处理离线推进与时钟篡改，与"极致轻"冲突 |
| **戒指大容量 / 无条件保底**（v0.5 高危） | 玩家最优解变为"搜到就存" → 行囊永远空着 → 失败零代价 | **撤离决策失去动机，搜打撤退化为扫荡模式**，SM-4 的紧张感归零 |
| **戒指容量 ≥ 行囊容量**（v0.5 高危） | 风险格失去意义，二分结构失效 | 等价于没有安全格机制 |
| **"空间戒指物资部分对冲队伍负担"**（v0.3 写法） | 与"轻度负担"叠加 → 招募零代价 | 队伍张力名存实亡 |
| **"轻度负担"**（消耗随人数增长但不严惩） | 同上，与戒指对冲形成双重削弱 | 招募决策变成无脑选"是" |
| **开局即无双**（戒指容量一开始就很大） | 摧毁前中期张力 | 难度塌陷，红区风险成真 |
| **奖励 = 自动通关 / 无限资源** | 会杀死游戏张力 | SM-C2 反向指标失效 |
| **纯 LLM 生成主线 / 生成风险数值** | 剧情飘忽、数值不确定 | 与"规则层兜底幻觉"的纪律冲突 |
| **全人工撰写所有文本** | 工程量过大 | MVP 无法在合理周期内完成 |
| **实时 AI 视频生成** | 成本与延迟硬约束 | 直接落在红区 |
| **sanity 高惩罚（可直接致死）** | 与"爽感内核"定位冲突 | 体验变成"又爽又丧"，定位撕裂 |
| **单次出击失败 = 游戏结束** | 14 天主线无展开空间 | 玩家在第 2 次出击就 game over，叙事体验归零 |
| **基地设施被出击失败摧毁** | 挫败感超过可承受阈值 | 玩家不敢出击，核心循环停摆 |
| **复杂生产链 / 设施布局规划 / 多基地** | 与"MVP 极致轻"冲突 | 范围失控 |

## E. 垂直切片策略的取舍

**为什么先做切片（1 区 + 1 伙伴 + 1 危机升级），而不是一次做满 MVP？**

| 维度 | 切片先行 | 一次做满 |
|---|---|---|
| 发现设计问题的成本 | 低——**风险累积曲线的手感问题会在切片期暴露** | 高——问题可能在内容做完后才暴露，返工面大 |
| 可验证的核心假设 | "出击→撤离→招募→升级→建造→奖励→结局"链路是否成立；**风险曲线是否真的制造出撤离决策** | 同上，但验证时点被推后 |
| 内容浪费风险 | 低 | 高——若数值手感不对，已产出的内容需重做 |
| 主要代价 | 全量 MVP 的交付时点后移 | 无 |

**关键前提（Q6）**：切片的"通过标准"必须**显式定义**，否则切片会无限延长。**建议标准（随 A24 更新）**——在无外部指导的情况下完成一局，且**主动发起第三次及以上出击**。

> **为什么不沿用"愿不愿意开第二局"**：A24 已定"按出击次数推进、存活 14 天封顶"，一局可长达 14 天，"第二局"概念不再适用。替代信号改为**同一局内的持续出击意愿**——这更能反映核心循环本身是否成立。

**切片期必须优先验证的四件事**（v0.6 增至四项）：
1. **风险累积曲线的手感**——玩家是否能感受到"再搜一个"的代价（Q7）
2. **容器二分的决策是否成立**——玩家是否会为"哪几件塞进戒指"认真犹豫
3. **失联后的痛感是否可承受**——太重会让人不敢出击，太轻则张力失效（Q8）
4. **每日系统抉择是否真的"不构成收入通道"** 🆕——跑通 B.9.3 的反闲置测试用例；同时观察玩家是否把它当成"每天的小决策"而非"领福利"（Q10）
